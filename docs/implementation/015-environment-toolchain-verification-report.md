## Next.js 15.5.22 security review

The newest registry-published Next.js 15.5 release observed was `15.5.22`.
`next` and `eslint-config-next` are both fixed to that version, with ESLint
remaining on compatible major 9.

The audit no longer reports a direct Next.js critical advisory. Remaining
production findings are transitive:

| Advisory | Dependency path | Installed | Vulnerable range | First non-vulnerable range | Scope |
|---|---|---:|---|---|---|
| GHSA-qx2v-qp2m-jg93 | `@rightjob/web -> next@15.5.22 -> postcss` | 8.4.31 | `<8.5.10` | `>=8.5.10` for this advisory | Production |
| GHSA-6g55-p6wh-862q | same | 8.4.31 | `<=8.5.11` | `>=8.5.12` | Production |
| GHSA-r28c-9q8g-f849 | same | 8.4.31 | `<=8.5.17` | `>=8.5.18` | Production |
| GHSA-f88m-g3jw-g9cj | `@rightjob/web -> next@15.5.22 -> sharp` | 0.34.5 | `<0.35.0` | `>=0.35.0` | Production, optional native dependency |
| GHSA-mh99-v99m-4gvg | ESLint/config/plugin dependency paths through `minimatch -> brace-expansion` | multiple | `brace-expansion <=5.0.7` | `>=5.0.8` | Development-only |

`npm explain postcss` shows that Next.js 15.5.22 requires PostCSS exactly
`8.4.31`. `npm explain sharp` shows that Next.js requires optional Sharp
`^0.34.3` and resolves `0.34.5`. The Next.js package manifest therefore does not
accept PostCSS `8.5.18` or Sharp `0.35.0`. There is no repository evidence that
Next.js 15.5.22 officially supports either out-of-range transitive release.

A root override is consequently **not** safer than waiting for an upstream
Next.js 15 patch: it would deliberately violate the framework's tested manifest,
shift native-binary compatibility risk to this repository, and create a
configuration that Next's maintainers did not publish. The ordinary safe paths
are an upstream supported Next.js 15 patch or a separately reviewed Next.js 16
migration. These findings remain a security condition.

Sharp was validated only through a normal `npm ci`, production build, and
production startup. The earlier `--ignore-scripts` lock operation is not treated
as runtime validation.

## Remaining conditions

1. **Python runtime/lock/install:** `make ci` fails with `uv: No such file or
   directory`; the only Python is 3.8.2. Provide a Python 3.11+ host with UV
   0.12 and registry access, generate `uv.lock`, run `uv sync --all-groups
   --locked`, then verify a second frozen install.
2. **Python validation/API:** Ruff, mypy, pytest, Alembic runtime, Python builds,
   FastAPI startup, `/health`, `/ready`, `/version`, unknown routes, and graceful
   API shutdown cannot be verified until condition 1 is resolved.
3. **Database:** Docker and psql are absent. Provide the approved PostgreSQL
   local runtime, then run clean migration apply, status, rerun, and database
   integration tests.
4. **Node security:** `npm audit --omit=dev` reports the exact PostCSS and Sharp
   advisories listed above. Next.js 15.5.22 does not declare compatibility with
   their patched releases. A supported upstream Next.js 15 patch is preferred;
   if none is published, Next.js 16 requires a separate migration decision and
   review.
5. **CI parity:** `make ci` cannot pass locally until Python and database
   conditions are resolved. Node-only gates pass.

These are concrete environment and supported-dependency conditions. They are not
architectural conflicts and are not being treated as proof of runtime security,
database isolation, or scale.
