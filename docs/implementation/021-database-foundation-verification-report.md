# Phase 2.1 Database Foundation Verification Report

**Date:** 2026-08-06  
**Scope:** Workspace, User, and Membership database foundation only  
**Migration:** `20260806_0001`  
**Verdict:** `PHASE 2.1 DATABASE FOUNDATION PASSED`

## Conflict resolution

The owner resolved the earlier model conflict: Workspace is the canonical tenant
boundary and agency account for MVP. Tenant describes Workspace isolation;
Organization and Agency are informal descriptions, not separate domain or persistence
entities. `workspace_id` is the only tenant key.

Workspace and User are Identity/Tenancy platform roots and therefore do not contain
`workspace_id`. Membership is tenant-owned, contains non-null `workspace_id`, and uses
direct forced PostgreSQL RLS. No Tenant or Organization model was created.

## ADR

[ADR-009](../decisions/adrs/ADR-009-workspace-as-mvp-tenant-and-agency.md) records the
combined Workspace boundary, rejected duplicate models, ownership, future expansion
gate, migration requirements, and tenant-isolation consequences.

Only the necessary terminology, decision log, and logical identity schema were
reconciled. No unrelated Constitution section was rewritten.

## Schema inventory

All application objects are owned by `rightjob_phase16_owner`. `plpgsql` is the only
installed extension; no Clerk, Temporal, `pgvector`, Redis, AI, Memory, Department, or
workflow object exists.

### `workspaces`

Columns: `id uuid`, `name varchar(255)`, `slug varchar(63)`, `status varchar(20)`,
`timezone varchar(100)`, `locale varchar(35)`, `settings jsonb`,
`created_at timestamptz`, `updated_at timestamptz`, `version integer`. All are non-null.

Constraints: `pk_workspaces`, `uq_workspaces_slug`, `ck_workspaces_slug`,
`ck_workspaces_status`, `ck_workspaces_version`.

Indexes: `pk_workspaces`, `uq_workspaces_slug`.

Access policy: Workspace is the tenant root. It is loaded only by exact Workspace ID
through the Identity/Tenancy Repository after authorized context resolution. No broad
application database privilege was introduced during this phase.

### `users`

Columns: `id uuid`, `external_identity_provider varchar(100)`,
`external_subject varchar(255)`, `email varchar(320)`, `display_name varchar(255)`,
`status varchar(20)`, `created_at timestamptz`, `updated_at timestamptz`,
`version integer`. All are non-null.

Constraints: `pk_users`, `uq_users_external_identity`, `ck_users_email_normalized`,
`ck_users_status`, `ck_users_version`.

Indexes: `pk_users`, `uq_users_external_identity`, `ix_users_email`. Email is normalized
but is intentionally not globally unique; the approved unique identity is provider plus
subject.

Access policy: User is a platform identity shared across Memberships. Identity-owned
queries may resolve the authenticated external identity or an authorized workspace
relationship. User is not falsely treated as a tenant row, and no authentication flow
or provider adapter was added.

### `memberships`

Columns: `id uuid`, `workspace_id uuid`, `user_id uuid`, `role varchar(20)`,
`status varchar(20)`, `created_at timestamptz`, `updated_at timestamptz`,
`version integer`. All are non-null.

Constraints: `pk_memberships`, `uq_memberships_workspace_user`,
`fk_memberships_workspace` (`ON DELETE RESTRICT`), `fk_memberships_user`
(`ON DELETE RESTRICT`), `ck_memberships_role`, `ck_memberships_status`,
`ck_memberships_version`.

Indexes: `pk_memberships`, `uq_memberships_workspace_user`,
`ix_memberships_workspace_user`, `ix_memberships_workspace_status`. Tenant query indexes
lead with `workspace_id`.

RLS: enabled and forced. Policy `memberships_workspace_isolation` applies to `ALL` using
and checking the transaction-local `app.current_workspace_id`. Missing or mismatched
context exposes no row and permits no write.

## Remaining risks

- Authentication and authorization are deliberately not implemented. A later accepted
  phase must map authenticated principals to the Identity-owned access patterns before
  granting application roles access to Workspace or User records.
- `updated_at` and optimistic `version` are schema foundations; mutation/concurrency
  behavior must be implemented and tested with future approved commands.
- Parent organizations and multi-workspace enterprise hierarchy remain prohibited
  without a new ADR and migration plan.
- Runtime security and scale beyond this isolated schema/RLS proof are not claimed.
